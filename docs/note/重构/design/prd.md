# PRD

## 1. 背景与问题

- 当前的产品的架构设计无法满足后续AI陪伴需求的开发，不能多场景输入，比如同时输入屏幕内容、直播间弹幕、ASR语音，并操控多个模块（TTS、live2d模型、可能还有游戏操作）
- 角色没有一个单独的大脑，控制她的整体行动。目前是分散成聊天和虚拟世界模块，而且虚拟世界耦合了角色行为选择和世界运转。
- 目前用户只能通过聊天模块与角色互动，形式比较单一，用户与角色的链接太少，角色无法给用户留下比较深的影响，而且难以推广。

## 我想做成什么样

- 为角色构建单独的大脑，统一的角色大脑，由主 loop 与场景 loop 组成，让角色有自己的意识，可以灵活添加各种场景的输入。角色的生活与行动由大脑决策，具体对话由聊天模块负责。
- 满足聊天、玩游戏、直播等场景，可以说话、可以驱动 live2d 模型进行表演。
- 虚拟世界抽离成单独的模块，角色大脑（agent loop）做接入，角色自己决策在虚拟世界里如何生活

## 新系统如何分工

- 聊天模块
- 角色大脑
- 虚拟世界

模块之间可以通过 API 进行通信，有查询和修改的能力，比如：查数据、修改计划等...

| 通信         | 协议      | 示例                             |
| ------------ | --------- | -------------------------------- |
| 角色查询世界 | HTTP      | 当前环境、角色状态、可参与的活动 |
| 角色请求行动 | HTTP      | 开始打工、中断活动、前往某地     |
| 世界通知角色 | WebSocket | 到达地点、工作结束、有人搭话     |

### 角色大脑

一直运行的 agent loop

她如何生活：关注什么、想做什么、如何行动

可以查询聊天模块的信息

大脑在经历一些有意思的事情时，也可以触发分享意图，分享自己的趣事

| 交互         | 具体含义                                   | 例子                                 |
| ------------ | ------------------------------------------ | ------------------------------------ |
| 获取当前感知 | 世界提供角色此刻可感知的信息               | 所在地点、附近的人、天气、正在做的事 |
| 主动查询     | 大脑主动获取角色有途径知道的信息           | 查看店里的招聘告示、查看自己的余额   |
| 发起行动     | 大脑提出行动，世界判断条件并开始执行       | 前往咖啡店、开始打工                 |
| 接收反馈     | 世界告知行动进展、结果及角色感知到的新事件 | 到达咖啡店、工作结束、有人走过来     |
| 中断行动     | 大脑提出停止，世界按规则处理后果           | 提前下班，按实际工作情况结算         |

- 实际状态归世界管理。 所在地点、余额、当前活动、活动进度等，由世界改变；大脑保存自己的打算，不能把“准备去咖啡店”当成“已经到了咖啡店”。
- 信息可见性由世界控制。 大脑以角色身份查询，世界只返回她有资格知道的信息，不能先把全量数据交给大脑再要求它忽略。
- 思考不会自动打断活动。 大脑产生新想法、回复聊天，都不影响正在进行的打工；只有明确发起相关行动，世界才处理状态变化。

大脑由事件驱动，虚拟世界是事件来源之一。

例如：

```
工作结束事件 → 悠酱思考下班后做什么 → 决定去公园 → 世界开始移动 → 到达公园事件 → 悠酱观察周围，决定下一步。
```

大脑正在思考时，又来了新事件，事件先收集起来，当前这一轮完成后，下一轮一起处理已经到达的事件

- 扩充「角色大脑」

角色大脑采用主 agent loop + 场景 sub-agent loop 的组织方式，代表同一个角色，共享角色身份与经历。
主 loop 负责日常生活决策、计划安排和进入特定场景，可以使用推理能力较强的模型。直播等对延迟敏感的场景使用独立的 sub-agent loop，配置适合该场景的模型、提示词和工具。
同一时间只有一个 loop 掌握角色的行动决策权。进入场景后，主 loop 等待场景结束，由场景 loop 接管当前活动；结束后交还控制权。
所有 loop 均由事件驱动。正在处理一轮决策时，新事件先收集起来，当前轮完成后，下一轮一起处理已经到达的事件。

- 「大脑与虚拟世界交互」

虚拟世界独立运行，负责世界规则、角色实际状态、持续活动的推进及结果。大脑负责决定角色想做什么，通过行动请求参与世界，不直接修改世界状态。
大脑只能获取角色能够感知或有途径查询到的信息，可见性由虚拟世界控制。
世界通过事件推动大脑运行，包括角色感知到的事情、行动进展和行动结果。大脑也可以主动查询当前状态。
活动可以有持续时间。活动期间，大脑仍能思考，角色仍能聊天；思考和聊天不会自动中断活动。是否允许中断或同时进行其他行动，由世界规则决定。

- 新增「场景接入」，先用直播说明

用户可以与角色提前约定直播，或指定直播日程。到达约定时间后，由事件触发主大脑决策，不直接自动进入直播。
开始直播前，角色必须位于家里。主大脑负责安排准备行动，虚拟世界检查开始直播的前置条件。
直播开始成功后，将直播安排、相关经历、当前状态和想法交给直播 loop。直播 loop 使用 flash 模型，接收直播相关事件，调用直播场景的工具。
直播期间，虚拟世界继续运行，但向角色发送的世界事件收窄为非常紧急的事件。普通事件不会因为未发送而阻止世界状态变化，也不默认积压到直播结束后补发。
紧急世界事件交给直播 loop 处理，由它决定如何回应以及是否结束直播。
直播结束后，主 loop 获得直播经历和最新状态，恢复日常决策及日常世界事件接收。
未来其他场景可以采用相同的控制权交接方式，并按需要配置各自的模型、输入和工具。

---

- 某些场景执行期间，例如直播，独立的 QQ 聊天模块不再回复，因为角色的注意力全在直播上了。
- 虚拟世界负责记录行动过程、结果及角色可感知的世界经历，并提供受角色视角限制的查询能力。

#### 日程计划

| 内容         | 用途                             | 直播例子                     |
| ------------ | -------------------------------- | ---------------------------- |
| 计划内容     | 想做什么，必要时说明目的         | 在家直播，聊最近玩的游戏     |
| 来源与背景   | 为什么有这个安排                 | 与群友约好周六直播           |
| 时间安排     | 什么时候准备、什么时候开始       | 19:30 准备，20:00 开始       |
| 当前进展     | 尚未开始、进行中、已完成、已取消 | 正在准备                     |
| 下次关注时间 | 什么时候再让大脑考虑这件事       | 19:30                        |
| 进展记录     | 已经做了什么，为什么调整         | 已出发回家；直播推迟到 20:15 |

- 形成计划。 当前掌握控制权的 loop 确定安排，保存计划，并明确下次关注时间。
- 时间到达。 计时机制产生“该关注这项计划了”的事件，不直接执行计划。
- 大脑考虑。 读取计划和当前状态，决定开始行动、继续等待、调整安排或取消。
- 世界执行。 如果发起行动，世界管理实际过程；大脑不等待整个活动结束。
- 事件推动后续。 到达地点、活动结束等事件到来后，大脑继续推进计划，更新进展。
- 结束或再次安排。 完成、取消，或者明确下一次关注时间。

#### 行为记录

我建议大脑每轮结束时，由程序保存这一轮“感知了什么、作了什么决定、实际执行了什么”。

收集一批事件 → 建立本轮记录 → 大脑查询信息、作出决定、调用工具 → 程序逐步记录调用结果 → 本轮结束，保存处理结果。

#### 长期记忆

- 异步从行为记录中整理记忆，角色记忆
- 人物画像，角色对每个人的印象
- 维护对生活的持续认识，不必逐条翻经历，也知道自己生活的大致情况。例如：打工是熟悉的日常；最近常去公园
